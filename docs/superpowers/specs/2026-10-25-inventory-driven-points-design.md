# 库存规格驱动的行情点位与自动报价设计

- 日期：2026-10-25
- 状态：已确认，已实现（2026-10-25）
- 关联规格：`docs/superpowers/specs/2026-10-23-steel-market-agent-design.md`

## 1. 背景与问题

现有 16 个公共行情点位覆盖 12 个品类，其中 12 个点位与实际经营业务不匹配，无法持续填入数据。库存表覆盖方管、矩管共 370 个唯一规格，且大多数规格有当日单价，是最稳定、最贴近经营的数据源。

用户目标：**按客户询价的任意规格快速报价**，同时让行情跟踪只围绕本公司实际经营的规格。

10.25 库存表实际数据质量：

- 371 行、370 个唯一规格（`(区块, 归一化规格)` 维度）。
- 3 个规格没有单价，只能建点位、不能生成当日行情。
- 另有 2 个规格有单价但没有支重，可以生成行情、不能计算客户报价。
- 因此：**370 个点位，367 条当日行情，365 个规格可报价**。

## 2. 目标与非目标

### 目标

1. 旧 16 个公共跟踪点停用，改为以库存表中的 370 个方管/矩管规格作为公共点位。
2. 每日导入库存 Excel 时，自动用库存单价生成当日行情，不再手工填写 Mysteel CSV。
3. 报价页支持选择全部可报价规格，快速生成报价单。
4. 保留版本回滚、审计、历史查询能力。

### 非目标（本期不做）

- 不为圆管、型材、板材、线材建立公共跟踪点；这些品类仍可通过“我的点位”创建私有点位。
- 不做 Mysteel 自动抓取，仍遵守人工授权数据约束。
- 不做生产环境 HTTPS、备份演练等部署硬化。
- 不新增数据库表结构。

### 反目标

- 不因去掉 16 个点位而丢失历史报价或审计记录。
- 不让 370 个点位把看板、日报或对话拖慢到不可用。
- 不在每次库存导入时产生重复的行情版本。
- 不让手工 CSV 覆盖并清空自动生成的当日行情。

## 3. 用户已确认的决定

1. 保留当前 10.25 库存导入结果，生效日期为 2026-10-25。
2. 原先 16 个点位不再使用，全部替换为库存表中的规格点位。
3. 行情价直接使用库存表“单价”自动生成，不再人工填报价 CSV。

## 4. 关键设计（含实现方决定）

### 4.1 点位编码与字段

- 唯一键：`(区块, normalize_spec(规格))`。同规格跨区块视为不同点位。
- 品类：库存区块“方管”映射为 `方管`；“矩形管”映射为 `矩管`。
- 地区：仓库名包含“昆明”时取 `昆明`；本期非昆明仓库不在业务范围内，编码使用仓库名的 ASCII 映射，无法映射时追加 4 位哈希，保证稳定。
- 规格：沿用库存表原文，例如 `100*100*2.5*6m`；匹配时使用现有 `normalize_spec`。
- 来源：`inventory`；单位：`元/吨`。
- 编码规则：
  `{FANG|JU}_{ASCII化规格}_{地区码}`
  - `x`、`×` 统一为 `X`；
  - `米` → `M`，`低` → `DI`，`Φ` → `PHI`；
  - 其他非 ASCII 字符视为编码失败，导入报错，避免悄悄产生不稳定编码；
  - 编码包含长度，避免 6m/12m 同截面冲突；
  - 例：`FANG_100X100X2.5X6M_KUNMING`、`JU_100X150X7.75X12M_KUNMING`；
  - 当前最长 31 字符，满足 64 字符限制。

### 4.2 重复规格与库存行选择

`120*120*3.75*6m` 出现两行，单价相同、支数分别为 2 和 268。

- 每个唯一规格只建一个点位、一条当日行情。
- 同类多行统一取“支数最大”的一行作为规范行；`pieces` 为空视为最小。
- 若多行单价不一致，仍取支数最大行，并产生 warning。
- `/api/quote/generate` 使用的 `find_inventory_item` 改为同一规则：按规格（可选品类）匹配，多行时取支数最大行，保证看板行情与报价取价一致。

### 4.3 旧点位处理与安全阈值

- 不物理删除旧点位，统一置 `is_active=false`，保留历史报价和审计；查询层过滤 inactive，界面上等同删除。
- 每次同步后，停用满足以下条件的公共点位：
  - `scope=public`；
  - `source in ('inventory','mysteel')`；
  - 不在本次库存规格集合中。
- 管理员手工创建的、非 inventory/mysteel 来源的公共点位不被自动停用。
- 私有点位不受影响。
- 防误删阈值：若本次待停用数量超过“当前由库存/旧行情驱动的 active 点位数”的 50%，且当前数量 ≥ 20，则跳过停用并返回 warning；运维可用 CLI `--force` 强制执行。避免残缺库存表一次性隐藏大量点位。
- `get_quotes`、历史查询、异动扫描增加 `PricePoint.is_active=true` 过滤，避免旧点位继续出现在行情、历史或异动中。

### 4.4 自动生成点位与行情

库存导入成功后，在同一数据库事务中执行：

1. 按 4.1 规则 upsert 公共点位（存在则更新并启用，不存在则创建）。
2. 按 4.3 规则停用旧点位。
3. 创建当日 `MARKET_QUOTE` 数据集版本：
   - 每个“有单价”的唯一规格一条 `MarketQuote`（10.25 为 367 条）；
   - `price = inventory.unit_price`；
   - `change = null`（由查询层按上一有效报价计算）；
   - `source = inventory`；
   - `note = 库存表单价`；
   - 导入批次文件名：`自动生成-{库存文件名}`。
4. 若当日行情 checksum 未变化，记录批次但不产生新版本，避免重复。

其他约束：

- 库存版本无变化时（重复导入同一文件），仍执行点位与行情同步，用于首次升级和补齐数据。
- 库存单价为空的规格仍创建点位，但不生成当日行情，并产生 warning。
- 库存导入 API 原有的日期缓存失效逻辑保持不变。
- 自动生成的行情批次在管理页可见（审计需要），但**不可单独回滚**：API 拒绝回滚 `file_name` 以 `自动生成-` 开头的行情批次；回滚库存批次会触发重新推导。UI 对这类批次禁用回滚按钮。

### 4.5 回滚

- 回滚库存批次后，从恢复后的 active 库存快照重新推导点位和行情，生成新的 `MARKET_QUOTE` 版本。
- 使用恢复后快照自身的 `snapshot_date`，不假设等于被回滚批次日期。
- 若回滚后没有 active 库存快照，则创建/切换为空的当日行情版本，使看板不再展示已被回滚的行情；点位不自动停用，只记录 warning。
- 旧点位历史数据保留，但因 inactive 不再出现在查询结果中。

### 4.6 手工报价 CSV 的去留

- 不再支持公共点位的手工报价 CSV 导入：
  - 移除管理页 CSV 上传入口与 `/api/admin/import/quotes` 公共导入路径；
  - 移除 `scripts/import_quotes_file.py` 的文档化用法与 16 点位模板流程；
  - `scripts/validate_business_data.py` 改为只校验库存 Excel，不再要求 Mysteel CSV。
- 私有点位报价继续通过“我的点位”页面单独录入。
- 现有 `import_quotes` 核心函数保留给历史测试/内部修复使用，但不再暴露为日常导入入口；若后续需要恢复，必须改为与自动行情合并而不是覆盖。

### 4.7 种子数据与运维 CLI

- `seed` 不再创建 16 个公共点位，只创建管理员与默认配置；空库首次导入库存后自动产生点位。
- 新增 `scripts/sync_inventory_points.py --date YYYY-MM-DD [--force]`：
  - 从指定日期的 active 库存快照重新推导点位与行情；
  - 用于已部署环境迁移、回滚修复和数据修复；
  - 使用第一个 admin 作为审计用户。

### 4.8 查询与前端

- `MAX_PAGE_SIZE` 从 100 调整到 500，保证一次取回 370 条点位/库存。
- 报价页：
  - 规格下拉从 `/api/inventory?page_size=500` 动态加载；
  - 按方管/矩管分组，支持搜索；
  - 370 个规格全部展示；缺少单价或支重的规格置灰并提示“库存数据不全”，不可提交。
- 看板：
  - 报价区按品类 Tab（全部/方管/矩管）展示，支持规格搜索；
  - 显示报价总数与当前筛选数量（10.25 为 367 条）；
  - 库存表加载全部 371 行，前端分页。
- 管理页导入结果增加“启用/新增点位数、停用点位数、自动生成报价数”。

### 4.9 日报、对话与 MCP

- 日报事实数据仍加载全部报价用于统计与异动。
- 发给 LLM 的报价明细和事实稿只列涨跌绝对值前 30 条，并附带总数；首日全部 `change=null` 时，按品类/规格排序取前 30 条，并注明“首日无涨跌”。
- 来源仍保留全部报价来源，用于审计。
- MCP `get_meta` 改为支持 `category`、`query`（规格子串）和 `limit`（默认 100，最大 500），返回 `total` 与精简字段；避免一次把 370 个点位全量塞进对话上下文。
- MCP `get_quotes` 默认返回前 50 条并返回 `total`；调用方可用 `limit` 调整。
- MCP `generate_daily_report` 与日报使用同一 30 条上限。
- 移除引用旧点位的价差对，改为：
  `FANG_100X100X2.5X6M_KUNMING` - `JU_100X150X2.5X6M_KUNMING`，名称“方管-矩管价差”。

### 4.10 涨跌口径

- 沿用现有规则：导入时显式提供的 `change` 优先；否则用同一 active 版本中上一有效报价日期计算。
- “上一有效报价”指同一 active 数据集版本下、严格早于当前日期、且点位 active 的最近一条报价。
- 10.25 是新区位首日，所有涨跌为空；看板显示“-”，异动不产生价格异动，日报按 4.9 处理。

## 5. 迁移步骤

1. 部署新代码并重启容器（无表结构变更）。
2. 用 10.25 库存文件重新导入，或执行 `scripts/sync_inventory_points.py --date 2026-10-25`。
3. 确认：370 个公共点位、16 个旧点位 inactive、10.25 有 367 条行情、365 个规格可报价。
4. 打开看板与报价页验收。

## 6. 验收标准

1. 公共点位为 370 个方管/矩管规格，旧 16 个点位不再出现在任何界面/查询。
2. 看板可看到 10.25 的 367 条行情，价格与库存表一致；重复规格只出现一次。
3. 报价页展示 370 个规格，其中 365 个可成功生成报价单；5 个数据不全规格置灰并给出原因。
4. 重新导入同一库存文件不产生重复行情版本。
5. 导入新一天库存后，自动生成新日期行情；历史日期可查。
6. 回滚库存批次后，行情与恢复后的库存一致；无恢复快照时当日行情为空。
7. 日报、异动、对话查价不因点位数量增加而报错；日报报价明细不超过 30 条且有总数。
8. MCP `get_meta` 不会一次返回超过 limit 的点位；`get_quotes` 默认不超过 50 条。
9. 公有点位的手工 CSV 导入入口已移除；私有点位功能不受影响。
10. 后端全量测试、前端构建、部署静态校验通过。

## 7. 风险

- 370 个卡片的看板渲染与接口体积增大；通过一次加载 + 前端筛选控制。
- 日报/对话上下文变长；通过前 30/50 条 + 总数控制。
- 旧点位历史在新模型下不可见；数据保留但 UI 等价删除，需业务接受。
- 库存单价是报价唯一来源，库存表漏填/填错会直接反映到行情；10.25 已有 5 个规格数据不全。
- 手工公共 CSV 入口移除是行为变更；若未来需要外部行情，应重新设计合并或独立来源，而不是覆盖自动行情。
