【v1.1 修订记录】
1. 调整依赖顺序：上传安全先于导入接口；知识库管理并入 RAG 阶段；日报生成移入 Agent 阶段；会话持久化并入 SSE 步骤。
2. 明确导入错误三分法：缺失点位=warning；格式/数值/负价格=行级错误并整批回滚；支售价公式偏差=warning。
3. RAG 从 MCP 阶段拆出，独立成阶段。
4. 新增环境准备、初始 admin、app_config 默认值、点位可获取性核对、CSV 模板、版本保留清理、备份脚本、CHANGELOG。
5. 补充 REST 报价直算接口、用户侧私有点位页面。
6. 补充 TDD 与 DoD、LLM 上下文与提示词管理、熔断告警、SSE 细节、缓存验收修正、审计矩阵、知识库入库安全、按服务指标。
7. 修正工期估算与 CI 时序；V2 占位收敛为两处明确接口。
8. 当前仓库已初始化（main 分支、规格已提交），不再重复 git init。
9. MCP Server 阶段调整到 RAG 之前，保证 Chroma 内嵌与内部入库接口的依赖顺序正确。


【开发原则】
1. TDD：每个步骤先写失败测试，再实现，再重构；不把测试集中在阶段末尾。
2. 自底向上：先数据底座，再业务核心，最后接口与前端。
3. steel_core 为唯一业务真相源，REST 与 MCP 共用同一套业务逻辑，不得各自实现计算。
4. MCP 工具严格只读；所有写操作统一走 REST 接口。
5. 鉴权、权限隔离、审计日志与功能同步落地，不延后补全。
6. V2/二期只保留两处明确预留：reranker no-op 接口、数据源导入适配器接口；不创建空模块。
7. Git 规范：每个步骤一个 feature 分支或清晰提交；Conventional Commits；阶段结束做一次代码评审。
8. DoD（完成定义）：代码 + 单元/集成测试 + README/接口文档更新 + CI 通过；缺一项不算完成。
